# CARLA RGB-D fusion

`carla_main.py` now uses aligned RGB and depth camera actors. Both use the same
mounting transform, image dimensions, field of view, lens parameters and sensor
tick. The default mode is now `TRAJECTORY_PREDICTION_TEST` (see README);
select `RGBD_DISTANCE_TEST` to repeat the completed distance test. Traffic-light validation is
still available by selecting `TRAFFIC_LIGHT_TEST` explicitly.

Run from the existing environment, with the CARLA server running:

```powershell
.\.venv\Scripts\python.exe carla_main.py
```

The camera callback buffer retains at most eight frames per camera. Only equal
CARLA frame IDs and timestamps are paired; old frames are discarded and no pair
is processed twice. A two-second absence of fresh pairs holds the vehicle stopped.
The display accepts Q while waiting. Both cameras are stopped/destroyed on exit.

Raw BGRA depth is decoded into meters using
`1000 * (R + 256*G + 65536*B) / (256**3 - 1)`.
Reference: https://carla.readthedocs.io/en/0.9.8/ref_sensors/#depth-camera

For each tracked box we sample its central 50% in each dimension, clip to the
image, discard nonfinite, zero and saturated depths, and take the median. At
least four valid pixels and 50% valid coverage are required. Invalid measurements
are marked `CARLA_DEPTH_INVALID`/NaN, and physical objects with invalid depth
request STOP. CARLA never falls back to image-position-based simulated range.
The legacy `fuse()` remains available to the separate webcam entry point.

Inspect logs for `RGB-D: ... matched=True` and per-track
`source=CARLA_DEPTH`, metric depth and sample count. The overlay shows the consumed
frame ID. These are camera-relative surface depths, not ego-to-object-center
distances. Existing NPC center-to-center ground truth is not a directly comparable
error reference. Box sampling can still measure an occluder or background; it
does not prove actor association. Depth is generated by the simulator, not a
physical depth sensor. Prediction remains in image coordinates in this version.

Local data-path validation:

```powershell
.\.venv\Scripts\python.exe -m unittest test_rgbd -v
```

Live validation still requires a CARLA run. Check consistent frame pairing and
decreasing per-track depth while approaching the stationary NPC. Quantitative
accuracy claims require matching the detected actor and comparing against a
camera-relative surface reference at the same simulation frame. Existing risk
thresholds have not been recalibrated for metric depth.

Traffic-Light Validation is closed based on the supplied run:
`TRAFFIC_LIGHT_TEST_PASSED`, RED/YELLOW/GREEN all PASS. This is separate from
pending live RGB-D validation.

## Independent distance validation

`RGBD_DISTANCE_TEST` adds a semantic ray-cast LiDAR **only as a validation
reference**, not as a perception/decision input. It has the camera's mounting
pose and its measurements must match the RGB-D frame, timestamp and world pose.
The test owns synchronous ticks at 20 Hz and restores the previous world
settings on exit. Run it without another tick-owning client. Camera distortion
is disabled in this test for pinhole projection of LiDAR points.

Semantic LiDAR points carry the actual actor ID hit by each ray. Points are
projected into each vehicle detection's central ROI; association requires at
least 20 NPC points, at least 90% NPC purity, and coverage spanning half the ROI
width and height. Multiple qualifying detections are ambiguous and remain WAIT.
No points/occlusion/insufficient coverage also remain WAIT, never PASS.

The independent reference is the median camera-forward surface depth of those
NPC points (`x` in the co-located sensor frame). Compare it to the existing
RGB-D ROI median. PASS requires absolute error <= max(0.5 m, 5% of reference).
This is an explicit prototype acceptance tolerance, not a claimed sensor
specification. Ray-cast collision surfaces and rendered surfaces/sampling can
differ; investigate failures rather than silently increasing tolerance.

Ten distinct consecutive passing frames finish the test with
`RGBD_DISTANCE_TEST_PASSED`. After 200 attempts it finishes without a pass.
The vehicle is stopped before either normal test completion. Results, tolerance,
frame/track/actor IDs, reference samples and errors are saved to
`rgbd_validation_report.json` beside the entry point. A sensor timeout is a
failure, not a successful validation. Switch back to `NORMAL` for ordinary driving.

This validates the observed scene and tolerance, not all actors/weather/ranges.
Local tests use synthetic reference geometry; a live CARLA result is still needed.

```powershell
.\.venv\Scripts\python.exe -m unittest test_rgbd test_rgbd_validation -v
```

Reference API: https://carla.readthedocs.io/en/latest/python_api/#carla.SemanticLidarDetection
